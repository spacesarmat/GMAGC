# GMAGC: поиск гобо по фото

Автор: @ANDY_BUM ([Telegram](https://t.me/Andy_bum)). Проект бесплатный; если он вам полезен, автора можно [поддержать](https://boosty.to/djmaker/donate). Лицензия: [MIT](LICENSE).

Находит в библиотеке гобо (папка в структуре grandMA) файл, который лучше всего совпадает с **фотографией проекции** на стене или экране. Выдаёт несколько лучших вариантов: название, путь, оценку совпадения; одинаковые гобо из разных папок производителей собираются в одну карточку.

**Статус: ПК-приложение с поиском и сервером, Android-клиент с камерой, автообновление, установщик для Windows (v0.9.0), сборки под Windows, macOS и Android.** В окне ПК-приложения выбирается папка библиотеки, строится индекс и ищется гобо по фото (файл, буфер обмена или телефон по Wi-Fi), результаты показывают превью, имя, путь (клик копирует его в буфер) и оценку. Android-приложение подключается к ПК по Wi-Fi (сканирует QR-код автоматически, без нажатия кнопки) и снимает проекцию камерой во весь экран (с приближением и фокусом), экран зафиксирован в вертикальном положении. Ядро, сервер, клиент, командная строка, бенчмарк и вспомогательные скрипты покрыты тестами (см. `docs/superpowers/specs`).

## Как это работает

Фото → поиск проекции (яркая малонасыщенная область, пятна узора сливаются в одну) → нормализация до 224×224 → 48 вариантов запроса (24 поворота × зеркало) → вектор признаков → косинусный поиск по кэшу индекса → мягкое сравнение формы для 20 лучших семейств дублей → результаты по семействам. Всё работает **офлайн**.

Вектор признаков сменный (`Embedder`): по умолчанию простой пиксельный вектор 16×16, без модели. Готовая нейросеть DINOv2-small на этих данных оказалась хуже и медленнее, подробности в `docs/benchmarks/2026-09-19-core-matcher.md`.

## Быстрый старт

Нужен Python 3.12+ (проверено на 3.14).

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PYTHONPATH = "apps\desktop\src"    # bash: export PYTHONPATH=apps/desktop/src

# один раз (и после изменений в библиотеке; при повторном запуске дозаписываются только новые файлы)
.venv\Scripts\python.exe -m gmagc_desktop.cli index D:\путь\к\gobos --index .gmagc-cache\index.npz

# поиск по фото
.venv\Scripts\python.exe -m gmagc_desktop.cli search photo.jpg --index .gmagc-cache\index.npz --library D:\путь\к\gobos --top 10
```

Пример вывода поиска: ` 1.  87.3%  vendor/ell.png  (+1 copies)`. Коды выхода: `0` успех; `1` индекса нет, он пуст или не подходит к модели; `2` проекция на фото не найдена; `3` не удалось прочитать входной файл (фото, модель, папка библиотеки).

## Результаты замеров

На 17 реальных фото (11 размечены, у 6 нужного гобо в библиотеке нет): верный ответ в первой пятёрке у **91%** (10 из 11), на первом месте у 64%. Поиск ~80 мс, индексация 11 тыс. файлов около минуты. Выборка небольшая (одна стена, одна камера), цифры показывают порядок величин.

## ПК-приложение

При запуске недолго показывается заставка с логотипом, пока грузятся настройки и индекс. Оформление всегда тёмное. Слева — боковая панель с навигацией по четырём экранам: «Поиск гобо», «Телефон», «Библиотека» и «Настройки» (внизу панели — статус приложения, автор и версия). Заголовок экрана поиска показывает метрики: число гобо в базе, время последнего поиска и лучшую оценку совпадения. Внизу окна — строка статуса (индекс построен/не построен, устройство, версии Python и Flet).

1. «Выбрать папку…»: папка библиотеки гобо. Индекс строится в фоне (с прогрессом и отменой) и сохраняется; при «Обновить индекс» (или клавише **F5**) дозаписываются только новые файлы. Если библиотека изменилась после сборки индекса (новые, изменённые или удалённые файлы), под статусом появляется напоминание обновить его. Прежний файл индекса перед перезаписью сохраняется рядом как `index.npz.previous` — если новый файл потеряется или повредится, следующий запуск сам подхватит резерв вместо долгой пересборки с нуля.
2. «Выбрать фото…» или «Вставить из буфера» (**Ctrl+V**; картинка или файл, скопированный в Проводнике): показываются исходное фото, найденная проекция и лучшие совпадения. Под фото и под проекцией — по три ползунка (яркость, контраст, экспозиция): первые правят исходное фото ещё до поиска самой проекции на кадре, вторые — уже найденную проекцию перед сравнением с библиотекой. Помогает, если фото размыто или пересвечено. Сбрасываются на нейтральные значения при каждом новом фото, каждая группа — своей кнопкой «Сбросить».
3. **Клик по карточке результата копирует в буфер обмена абсолютный путь файла вместе с именем** (`C:\...\файл.png` на Windows, `/Users/.../файл.png` на macOS); значок папки на карточке открывает файловый менеджер с выделенным файлом. Если оценка первого результата ниже 72%, приложение предупреждает, что совпадение ненадёжно. Если проекция на фото не найдена, предлагается переснять ближе и затемнить фон.
4. Если результат неверный — значок недовольного пальца на карточке («Это не то») позволяет указать верный файл из библиотеки. При следующих похожих запросах верный файл подставляется первым (с высокой оценкой), а прежний неверный результат остаётся в списке ниже, не пропадает. Это не переобучение модели (готовая нейросеть DINOv2 на этих данных проверялась и оказалась хуже, см. ниже) — простая надстройка на парах «неверный → верный», хранится рядом с индексом и сбрасывается при смене библиотеки. Работает и для результатов, пришедших с телефона.

Экран «Настройки» собирает «Крупный текст», автозапуск, «Число результатов поиска» (10, 20, 50 или 100; по умолчанию 50 — на настоящей библиотеке 100 результатов считаются около полусекунды, телефону это не влияет), «Экспорт настроек» / «Импорт настроек» (файл `.json`, пригодится при переустановке или переносе на другой ПК — сервер и код доступа из импортированного файла применяются после перезапуска), проверку ядра, проверку обновлений, ссылки поддержки автора и «Отправить лог по почте». Последний пункт открывает письмо на автора с версией, ОС и статусом индекса и показывает файл лога (`gmagc.log`, ротация 1 МБ) в проводнике/Finder — приложить к письму нужно вручную, само приложение почту не отправляет.

## Сервер для телефона

Сервер стартует **вместе с приложением** (переключатель «Сервер для телефона» на экране «Телефон» выключает его и запоминает выбор). Экран «Телефон» показывает адрес ПК, QR-код и **постоянный код доступа** из 8 символов (кнопки «Копировать код» и «Новый код»). ПК и телефон должны быть в одной сети Wi-Fi; при первом запуске Windows спросит разрешение в брандмауэре, его нужно дать для частных сетей. Порт 8765, если он занят, берётся следующий (он виден в окне и в QR). Запросы с телефона сразу показываются в основном окне и попадают в список «Запросы с телефона» (последние 10, клик открывает результат).

«Автозапуск при включении компьютера» (Windows и macOS) добавляет GMAGC в автозагрузку текущего пользователя (реестр `HKCU\...\Run` на Windows, LaunchAgent на macOS) — без прав администратора и без сворачивания в трей: окно при этом открывается как обычно.

Протокол (HTTP, только локальная сеть, без облака), общий код лежит в `packages/common/gmagc_common`:
- `GET /api/health`: версия API, есть ли индекс (без кода);
- `GET /api/status`: файлы, семейства, идёт ли индексация;
- `POST /api/match[?top=N]`: тело запроса это JPEG/PNG (до 10 МБ), ответ: исход, время, результаты (имя, полный путь на ПК, оценка, копии, превью в base64) и найденная проекция.

Все методы кроме `health` требуют `Authorization: Bearer <код>`; после 5 неверных кодов с одного адреса сервер отвечает 429 на 30 секунд. Ошибки приходят JSON-ом (`{"error": "unauthorized", "message": "..."}`).

Проверить без телефона можно скриптом, который делает то же, что делал бы телефон (уменьшает фото до 1280 px и отправляет):

```powershell
.venv\Scripts\python.exe scripts\phone_sim.py --host 192.168.1.5 --port 8765 --code ABCD-2345 photo.jpg
# или по ссылке из QR: --link "gmagc://connect?host=192.168.1.5&port=8765&code=ABCD2345"
```

Коды выхода: `0` успех, `1` сервер ответил ошибкой, `2` нет соединения, `3` неверные аргументы или нечитаемое фото.

Настройки и кэш индекса лежат в `%LOCALAPPDATA%\@ANDY_BUM\GMAGC\` (macOS `~/Library/Application Support/GMAGC`, иначе `~/.local/share/gmagc`); путь можно переопределить переменной `GMAGC_DATA_DIR`. Перетаскивание файлов из ОС во Flet 1.0.0 не поддерживается, поэтому фото выбираются кнопками.

## Android-приложение

Установите `GMAGC-android-<версия>.apk` (разрешите установку из неизвестных источников) и держите телефон в **той же сети Wi-Fi**, что и ПК с запущенным GMAGC (блок «Телефон» в окне ПК показывает адрес, QR и код). Оформление всегда тёмное, независимо от системной темы.

1. **Подключение.** Сверху — логотип и название, ниже поля адреса и кода на всю ширину, кнопка «Подключиться» и кнопка «Считать QR-код с ПК» (наводите камеру на QR-код в окне ПК — считывается и подключается автоматически, без нажатия кнопки; приближение и касание кадра для фокуса помогают). Если автосканирование не сработает, вместо кнопки появится «Считать QR» (снимок вручную). Подключение запоминается и восстанавливается при запуске. Внизу экрана неподвижно закреплена навигация «Настройки» / «Помощь» / «О программе».
2. **Камера** (во весь экран, углы видоискателя обозначены цветными скобками; всё управление плавает поверх кадра). Сверху слева — навигация «Галерея» / «Настройки» / «О программе», сверху справа — значок Wi-Fi (зелёный — подключено, красный — нет) вместо заголовка. Приближение: вертикальный ползунок и кнопки лупы справа, или щипок двумя пальцами. Фокус: значок снизу слева (касание кадра дополнительно наводит фокус и замер экспозиции, жёлтая метка). Круглая кнопка «Сфотографировать» снизу по центру отправляет кадр на ПК, «Выбрать фото» снизу справа — из галереи устройства (большие файлы сжимаются до 8 МБ). Кнопка «Назад» с камеры сразу возвращает на экран подключения.
3. **Результаты.** Превью, имя, путь на ПК, оценка, «ещё N файлов». **Клик по карточке или «Копировать путь» кладёт в буфер абсолютный путь файла с именем.** «Снять ещё» возвращает к камере.
4. **Галерея** — история снимков этой сессии (последние 10); клик по записи показывает тот же результат заново без повторной отправки фото на ПК.
5. **Настройки** — проверка обновлений, «Сменить ПК» (забывает текущее подключение).
6. **О программе** — версия, автор, ссылки поддержки.

Ошибки показываются понятным текстом (нет связи, неверный код, индекс на ПК не построен, слишком много неверных кодов); при сбое сети кнопка «Повторить» отправляет тот же снимок ещё раз без пересъёмки. Внизу экрана подключения остаётся строка «Последняя ошибка» для диагностики. На ПК (`flet run apps/mobile/src/main.py`) вместо камеры показывается заглушка, работают подключение и «Выбрать фото» (для отладки: `GMAGC_MOBILE_DEMO_LINK` подключается по ссылке из QR, `GMAGC_MOBILE_DEMO_PHOTO` сразу ищет по файлу).

Окно «Профили» (кнопка на экране подключения и на экране камеры) создаёт с нуля профили приборов для grandMA2 и grandMA3: производитель, название, режимы, каналы (из шаблонов: диммер, Pan/Tilt, цвет, гобо, призма и др.; 8 или 16 бит; DMX-адрес подставляется сам), диапазоны значений с названиями. Проверка показывает пересечения адресов и дыры в диапазонах, все правки сохраняются сразу. Кнопки «Поделиться» отдают **готовые файлы** через системное меню (в мессенджер, почту, на компьютер): JSON профиля, XML типа прибора для grandMA3 (кладётся в `C:\ProgramData\MALightingTechnology\gma3_library\fixturetypes` и импортируется в MA3) и по одному XML на режим для grandMA2 (в `importexport` MA2; у MA2 один файл описывает один режим). То же делают скрипты `scripts/export_ma3.py` и `scripts/export_ma2.py` по JSON профиля. Каналы «Ирис», «Фрост», CTO, «Управление» и «Свой канал» в MA2 пока выгружаются пустыми, слоты колёс не создаются. Отправка на ПК запланирована следующим этапом (см. `docs/superpowers/specs/2026-09-24-gmagc-fixture-editor-design.md`).

## Обновления

Приложения сами узнают о новой версии на GitHub Releases: через несколько секунд после запуска, не чаще раза в сутки, плюс кнопка «Проверить обновления» (на ПК в верхнем меню, на Android на экране «Настройки»). Проверку можно выключить переключателем «Проверять обновления». Нет сети или ответа GitHub: тихо ничего не происходит, приложение остаётся полностью офлайн.

- **ПК (Windows, macOS):** при новой версии вверху окна появляется полоса «Доступна версия X (у вас Y)» с кнопками «Обновить», «Что нового» (страница релиза) и «Пропустить». «Обновить» скачивает архив, **сверяет SHA-256 с файлом `.sha256` из того же релиза** (без суммы или при несовпадении файл не ставится), распаковывает во временную папку, закрывает приложение; небольшой скрипт заменяет файлы, прежняя версия остаётся рядом в папке `<папка приложения>.previous`, и запускается новая версия. Настройки и индекс лежат вне папки приложения и не затрагиваются. Если папка недоступна для записи или что-то не сошлось, показывается причина и ссылка на страницу релиза.
- **Android:** полоса «Доступна версия X» с кнопкой «Скачать» открывает APK в браузере, дальше обычная установка Android (тихо ставить APK система не разрешает). Обновление ставится поверх, потому что все APK подписаны одним постоянным ключом (см. ниже); версии до 0.5.2 подписаны временными ключами, их нужно один раз удалить и поставить заново.
- Только HTTPS и адреса `github.com` / `*.githubusercontent.com` (проверяется каждый переход). Сборки не подписаны, а сумма лежит в том же релизе: она защищает от повреждённой загрузки, но не от взлома аккаунта GitHub, поэтому установка идёт только по кнопке.
- Для отладки `GMAGC_UPDATE_URL=http://127.0.0.1:<порт>/latest` подменяет GitHub (принимается только локальный адрес).

## Сборки (Windows, macOS, Android)

Сборки делает GitHub Actions: по тегу `v*` (например `v0.2.0`) в релиз попадают `GMAGC-desktop-windows-<версия>.zip`, `GMAGC-Setup-<версия>.exe` (то же самое, но установщиком: ставит в `%LocalAppData%\Programs\GMAGC` без прав администратора, добавляет ярлык и запись в «Установка и удаление программ»; собирается [Inno Setup](https://jrsoftware.org/isinfo.php) из `packaging/windows/gmagc.iss`), `GMAGC-desktop-macos-<версия>.zip`, `GMAGC-android-<версия>.apk` и файлы `.sha256`. Те же сборки запускаются вручную (Actions → нужный workflow → Run workflow, артефакты лежат в запуске) — на Pull Request не запускаются, чтобы не грузить и так ограниченный пул macOS-раннеров параллельно с тестами. Автообновление всегда использует zip — устанавливать `.exe` вручную нужно только один раз.

ПК-приложение ищет по фото и принимает снимки с телефона, Android-приложение снимает и отправляет их (см. выше и ниже). Приложения без подписей:
- macOS: правый клик по приложению → «Открыть»;
- Windows: SmartScreen → «Подробнее» → «Выполнить в любом случае»;
- Android: разрешить установку из неизвестных источников.

**Подпись Android.** APK подписывается постоянным ключом (иначе телефон не даёт поставить новую версию поверх старой): ключ и пароль лежат вне репозитория у автора (`GMAGC-keys`) и в секретах GitHub `ANDROID_KEYSTORE_B64` и `ANDROID_KEYSTORE_PASSWORD`, workflow сверяет отпечаток подписи (`apksigner verify`). **Потеря ключа означает, что уже установленные приложения нельзя обновить**, поэтому копию ключа нужно хранить в надёжном месте. Сборки из форков без секретов подписываются временным отладочным ключом.

APK собирается только под **arm64-v8a** (`target_arch`, около 58 МБ; все современные телефоны; для 32-битных ARM и эмуляторов x86_64 соберите свой APK: `flet build apk apps/mobile --arch armeabi-v7a`).

Настройки Android-сборки лежат в `apps/mobile/pyproject.toml`: `permissions = ["camera"]` (разрешение камеры в манифесте) и `[tool.flet.android.manifest_application] usesCleartextTraffic = "true"` (HTTP по локальной сети). Для чтения QR нужны колёса `pyzbar` и `Pillow` (есть на pypi.flet.dev), тесты чтения QR в CI ставят библиотеку zbar.

Версия Flet записана в четырёх местах и меняется вместе: `FLET_VERSION` в трёх `build-*.yml`, `dependencies` в `apps/*/pyproject.toml` и `requirements-dev.txt`. Версия приложения (`VERSION` в `about.py` обоих приложений, `version` в их `pyproject.toml`) меняется вместе с тегом.

## Локальная разработка (Windows)

Один раз: Python 3.12 (`winget install Python.Python.3.12`), Visual Studio 2022 с «Desktop development with C++», режим разработчика Windows. Окружение для сборки: `py -3.12 -m venv $env:USERPROFILE\.venv312`, затем `$env:USERPROFILE\.venv312\Scripts\python.exe -m pip install flet==1.0.0 -r requirements-dev.txt` (Flutter Flet скачает сам).

| Что | Команда | Время |
|---|---|---|
| Тесты и линтер | `.venv\Scripts\python.exe -m pytest -q`, `... -m ruff check .` | секунды |
| Экран без упаковки (горячая перезагрузка) | `$env:USERPROFILE\.venv312\Scripts\flet.exe run apps/desktop/src/main.py -d` | секунды |
| Сборка Windows + проверка запуска | `.\scripts\build_windows.ps1` | несколько минут |
| Финальные сборки Windows, macOS, Android | тег `v*` → GitHub Actions | ~10 минут |

Логи собранного приложения: `%LOCALAPPDATA%\@ANDY_BUM\GMAGC\console.log`. macOS локально на Windows не собрать, только через GitHub.

Значок приложения лежит в `apps/*/src/assets/icon.png` (Flet сам создаёт из него значки для Windows, macOS и Android); исходный рисунок: `docs/branding/icon.png`, фон подложки задан `icon_background` в `pyproject.toml`.
