# GMAGC: поиск гобо по фото

Автор: @ANDY_BUM ([Telegram](https://t.me/Andy_bum)). Проект бесплатный; если он вам полезен, автора можно [поддержать](https://boosty.to/djmaker/donate). Лицензия: [MIT](LICENSE).

Находит в библиотеке гобо (папка в структуре grandMA) файл, который лучше всего совпадает с **фотографией проекции** на стене или экране. Выдаёт несколько лучших вариантов: название, путь, оценку совпадения; одинаковые гобо из разных папок производителей собираются в одну карточку.

**Статус: ПК-приложение с поиском и сервером, Android-клиент с камерой, автообновление (v0.6.2), сборки под Windows, macOS и Android.** В окне ПК-приложения выбирается папка библиотеки, строится индекс и ищется гобо по фото (файл, буфер обмена или телефон по Wi-Fi), результаты показывают превью, имя, путь (клик копирует его в буфер) и оценку. Android-приложение подключается к ПК по Wi-Fi (сканирует QR-код автоматически, без нажатия кнопки) и снимает проекцию камерой во весь экран (с приближением и фокусом), экран зафиксирован в вертикальном положении. Ядро, сервер, клиент, командная строка, бенчмарк и вспомогательные скрипты покрыты тестами (см. `docs/superpowers/specs`).

## Как это работает

Фото → поиск проекции (яркая малонасыщенная область, пятна узора сливаются в одну) → нормализация до 224×224 → 48 вариантов запроса (24 поворота × зеркало) → вектор признаков → косинусный поиск по кэшу индекса → мягкое сравнение формы для 20 лучших семейств дублей → результаты по семействам. Всё работает **офлайн**.

Вектор признаков сменный (`Embedder`): по умолчанию простой пиксельный вектор 16×16, без модели. Готовая нейросеть DINOv2-small на этих данных оказалась хуже и медленнее, подробности в `docs/benchmarks/2026-09-19-core-matcher.md`.

## Быстрый старт

Нужен Python 3.12+ (проверено на 3.14).

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:PYTHONPATH = "apps\desktop\src"    # bash: export PYTHONPATH=apps/desktop/src

# один раз (и после изменений в библиотеке; при повторном запуске дозаписываются только новые файлы)
.venv\Scripts\python.exe -m gmagc_desktop.cli index D:\путь\к\gobos --index .gmagc-cache\index.npz

# поиск по фото
.venv\Scripts\python.exe -m gmagc_desktop.cli search photo.jpg --index .gmagc-cache\index.npz --library D:\путь\к\gobos --top 10
```

Пример вывода поиска: ` 1.  87.3%  vendor/ell.png  (+1 copies)`. Коды выхода: `0` успех; `1` индекса нет, он пуст или не подходит к модели; `2` проекция на фото не найдена; `3` не удалось прочитать входной файл (фото, модель, папка библиотеки).

## Результаты замеров

На 17 реальных фото (11 размечены, у 6 нужного гобо в библиотеке нет): верный ответ в первой пятёрке у **91%** (10 из 11), на первом месте у 64%. Поиск ~80 мс, индексация 11 тыс. файлов около минуты. Выборка небольшая (одна стена, одна камера), цифры показывают порядок величин.

## ПК-приложение

1. «Выбрать папку…»: папка библиотеки гобо. Индекс строится в фоне (с прогрессом и отменой) и сохраняется; при «Обновить индекс» дозаписываются только новые файлы.
2. «Выбрать фото…» или «Вставить из буфера» (картинка или файл, скопированный в Проводнике): показываются исходное фото, найденная проекция и лучшие совпадения.
3. **Клик по карточке результата копирует в буфер обмена абсолютный путь файла вместе с именем** (`C:\...\файл.png` на Windows, `/Users/.../файл.png` на macOS); значок папки на карточке открывает файловый менеджер с выделенным файлом. Если оценка первого результата ниже 72%, приложение предупреждает, что совпадение ненадёжно. Если проекция на фото не найдена, предлагается переснять ближе и затемнить фон.

## Сервер для телефона

Сервер стартует **вместе с приложением** (переключатель «Сервер для телефона» в левой колонке выключает его и запоминает выбор). Блок «Телефон» показывает адрес ПК, QR-код и **постоянный код доступа** из 8 символов (кнопки «Копировать код» и «Новый код»). ПК и телефон должны быть в одной сети Wi-Fi; при первом запуске Windows спросит разрешение в брандмауэре, его нужно дать для частных сетей. Порт 8765, если он занят, берётся следующий (он виден в окне и в QR). Запросы с телефона сразу показываются в основном окне и попадают в список «Запросы с телефона» (последние 10, клик открывает результат).

Протокол (HTTP, только локальная сеть, без облака), общий код лежит в `packages/common/gmagc_common`:
- `GET /api/health`: версия API, есть ли индекс (без кода);
- `GET /api/status`: файлы, семейства, идёт ли индексация;
- `POST /api/match[?top=N]`: тело запроса это JPEG/PNG (до 10 МБ), ответ: исход, время, результаты (имя, полный путь на ПК, оценка, копии, превью в base64) и найденная проекция.

Все методы кроме `health` требуют `Authorization: Bearer <код>`; после 5 неверных кодов с одного адреса сервер отвечает 429 на 30 секунд. Ошибки приходят JSON-ом (`{"error": "unauthorized", "message": "..."}`).

Проверить без телефона можно скриптом, который делает то же, что делал бы телефон (уменьшает фото до 1280 px и отправляет):

```powershell
.venv\Scripts\python.exe scripts\phone_sim.py --host 192.168.1.5 --port 8765 --code ABCD-2345 photo.jpg
# или по ссылке из QR: --link "gmagc://connect?host=192.168.1.5&port=8765&code=ABCD2345"
```

Коды выхода: `0` успех, `1` сервер ответил ошибкой, `2` нет соединения, `3` неверные аргументы или нечитаемое фото.

Настройки и кэш индекса лежат в `%LOCALAPPDATA%\@ANDY_BUM\GMAGC\` (macOS `~/Library/Application Support/GMAGC`, иначе `~/.local/share/gmagc`); путь можно переопределить переменной `GMAGC_DATA_DIR`. Перетаскивание файлов из ОС во Flet 1.0.0 не поддерживается, поэтому фото выбираются кнопками.

## Android-приложение

Установите `GMAGC-android-<версия>.apk` (разрешите установку из неизвестных источников) и держите телефон в **той же сети Wi-Fi**, что и ПК с запущенным GMAGC (блок «Телефон» в окне ПК показывает адрес, QR и код).

1. **Подключение.** «Считать QR-код с ПК» (наведите камеру на QR в окне ПК, при необходимости приблизьте и коснитесь кадра для фокуса, нажмите «Считать QR») либо введите «Адрес ПК» и «Код доступа» вручную. Подключение запоминается и восстанавливается при запуске; «Сменить ПК» его забывает.
2. **Камера.** Приближение: ползунок, кнопки лупы или щипок двумя пальцами. Фокус: касание кадра наводит фокус и замер экспозиции (жёлтая метка), «Фокус: авто / зафиксирован» фиксирует фокус. «Снять» отправляет кадр (1280×720) на ПК, «Из галереи» отправляет готовое фото (большие файлы сжимаются до 8 МБ).
3. **Результаты.** Превью, имя, путь на ПК, оценка, «ещё N файлов». **Клик по карточке или «Копировать путь» кладёт в буфер абсолютный путь файла с именем.** «Снять ещё» возвращает к камере.

Ошибки показываются понятным текстом (нет связи, неверный код, индекс на ПК не построен, слишком много неверных кодов), внизу экрана остаётся строка «Последняя ошибка» для диагностики. На ПК (`flet run apps/mobile/src/main.py`) вместо камеры показывается заглушка, работают подключение и «Из галереи» (для отладки: `GMAGC_MOBILE_DEMO_LINK` подключается по ссылке из QR, `GMAGC_MOBILE_DEMO_PHOTO` сразу ищет по файлу).

## Обновления

Приложения сами узнают о новой версии на GitHub Releases: через несколько секунд после запуска, не чаще раза в сутки, плюс кнопка «Проверить обновления» (на ПК внизу окна, на Android на экране подключения). Проверку можно выключить переключателем «Проверять обновления». Нет сети или ответа GitHub: тихо ничего не происходит, приложение остаётся полностью офлайн.

- **ПК (Windows, macOS):** при новой версии вверху окна появляется полоса «Доступна версия X (у вас Y)» с кнопками «Обновить», «Что нового» (страница релиза) и «Пропустить». «Обновить» скачивает архив, **сверяет SHA-256 с файлом `.sha256` из того же релиза** (без суммы или при несовпадении файл не ставится), распаковывает во временную папку, закрывает приложение; небольшой скрипт заменяет файлы, прежняя версия остаётся рядом в папке `<папка приложения>.previous`, и запускается новая версия. Настройки и индекс лежат вне папки приложения и не затрагиваются. Если папка недоступна для записи или что-то не сошлось, показывается причина и ссылка на страницу релиза.
- **Android:** полоса «Доступна версия X» с кнопкой «Скачать» открывает APK в браузере, дальше обычная установка Android (тихо ставить APK система не разрешает). Обновление ставится поверх, потому что все APK подписаны одним постоянным ключом (см. ниже); версии до 0.5.2 подписаны временными ключами, их нужно один раз удалить и поставить заново.
- Только HTTPS и адреса `github.com` / `*.githubusercontent.com` (проверяется каждый переход). Сборки не подписаны, а сумма лежит в том же релизе: она защищает от повреждённой загрузки, но не от взлома аккаунта GitHub, поэтому установка идёт только по кнопке.
- Для отладки `GMAGC_UPDATE_URL=http://127.0.0.1:<порт>/latest` подменяет GitHub (принимается только локальный адрес).

## Сборки (Windows, macOS, Android)

Сборки делает GitHub Actions: по тегу `v*` (например `v0.2.0`) в релиз попадают `GMAGC-desktop-windows-<версия>.zip`, `GMAGC-desktop-macos-<версия>.zip`, `GMAGC-android-<версия>.apk` и файлы `.sha256`. Те же сборки запускаются на Pull Request и вручную (Actions → нужный workflow → Run workflow), артефакты лежат в запуске.

ПК-приложение ищет по фото и принимает снимки с телефона, Android-приложение снимает и отправляет их (см. выше и ниже). Приложения без подписей:
- macOS: правый клик по приложению → «Открыть»;
- Windows: SmartScreen → «Подробнее» → «Выполнить в любом случае»;
- Android: разрешить установку из неизвестных источников.

**Подпись Android.** APK подписывается постоянным ключом (иначе телефон не даёт поставить новую версию поверх старой): ключ и пароль лежат вне репозитория у автора (`GMAGC-keys`) и в секретах GitHub `ANDROID_KEYSTORE_B64` и `ANDROID_KEYSTORE_PASSWORD`, workflow сверяет отпечаток подписи (`apksigner verify`). **Потеря ключа означает, что уже установленные приложения нельзя обновить**, поэтому копию ключа нужно хранить в надёжном месте. Сборки из форков без секретов подписываются временным отладочным ключом.

APK собирается только под **arm64-v8a** (`target_arch`, около 58 МБ; все современные телефоны; для 32-битных ARM и эмуляторов x86_64 соберите свой APK: `flet build apk apps/mobile --arch armeabi-v7a`).

Настройки Android-сборки лежат в `apps/mobile/pyproject.toml`: `permissions = ["camera"]` (разрешение камеры в манифесте) и `[tool.flet.android.manifest_application] usesCleartextTraffic = "true"` (HTTP по локальной сети). Для чтения QR нужны колёса `pyzbar` и `Pillow` (есть на pypi.flet.dev), тесты чтения QR в CI ставят библиотеку zbar.

Версия Flet записана в четырёх местах и меняется вместе: `FLET_VERSION` в трёх `build-*.yml`, `dependencies` в `apps/*/pyproject.toml` и `requirements-dev.txt`. Версия приложения (`VERSION` в `about.py` обоих приложений, `version` в их `pyproject.toml`) меняется вместе с тегом.

## Локальная разработка (Windows)

Один раз: Python 3.12 (`winget install Python.Python.3.12`), Visual Studio 2022 с «Desktop development with C++», режим разработчика Windows. Окружение для сборки: `py -3.12 -m venv $env:USERPROFILE\.venv312`, затем `$env:USERPROFILE\.venv312\Scripts\python.exe -m pip install flet==1.0.0 -r requirements-dev.txt` (Flutter Flet скачает сам).

| Что | Команда | Время |

Логи собранного приложения: `%LOCALAPPDATA%\@ANDY_BUM\GMAGC\console.log`. macOS локально на Windows не собрать, только через GitHub.
