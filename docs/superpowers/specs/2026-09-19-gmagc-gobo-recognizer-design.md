# GMAGC: распознавание гобо по фото. Дизайн

Дата: 2026-09-19. Статус: утверждён в брейншторме, ждёт проверки пользователем.

## 1. Цель

Программа находит в библиотеке гобо (папка в структуре grandMA, далее «библиотека») файл, который максимально совпадает с **фотографией проекции** на стене или экране. Выдаёт несколько лучших результатов: превью, имя файла, кликабельный путь, оценку совпадения.

## 2. Требования

1. Платформы: Windows, macOS (ПК-версия), Android (телефон/планшет).
2. Схема «сервер на ПК, клиент на телефоне»: телефон работает как камера и получает результаты от ПК.
3. Распознавание полностью **офлайн** (интернет не нужен ни при сборке индекса, ни при поиске). На ПК без телефона фото берётся из файла, перетаскиванием или из буфера обмена.
4. Стек: Python + Flet. Сборка под все платформы в GitHub Actions.
5. Фото: проекция на стене/экране либо картинка с экрана. Устойчивость к перспективе, цвету, яркости, поворотам, зеркалу, частичной обрезке и фоновому мусору.

Вне объёма первой версии: iOS, Linux, веб-клиент для телефона, вебкамера ПК, работа через интернет, цветовое сопоставление цветных гобо, дообучение модели.

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Что на фото | Проекция на стене/экране, картинка с экрана |
| Где библиотека | На ПК, путь задаётся в настройках, в git не хранится |
| Связь | Одна Wi-Fi сеть, подключение по QR + ручной ввод IP и кода |
| Архитектура | Два Flet-приложения (desktop и mobile) плюс общий пакет протокола |
| Распознавание | Гибрид: нейросеть (ONNX, офлайн) для поиска кандидатов + сравнение формы для уточнения |

## 4. Архитектура

```
GMAGC/
  packages/common/gmagc_common/   протокол: модели ответа, версия API
  apps/desktop/                   Flet-приложение (Windows/macOS): сервер + UI + распознавание
    gmagc_desktop/
      ui/         экраны: результаты, настройки, подключение (QR)
      server/     FastAPI + uvicorn в фоновом потоке
      library/    сканирование папки, кэш индекса
      matcher/    препроцессинг, эмбеддинги, поиск, уточнение
    pyproject.toml   Python 3.12; flet, fastapi, uvicorn, onnxruntime, opencv-python-headless, numpy, qrcode
  apps/mobile/                    Flet-приложение (Android): тонкий клиент
    gmagc_mobile/  ui/, client.py
    pyproject.toml   flet, flet-camera, flet-permission-handler, httpx (без numpy/OpenCV)
  tests/  scripts/  docs/  .github/workflows/
```

Границы модулей:
- `matcher` ничего не знает о UI и HTTP: вход — изображение, выход — список результатов. Интерфейс сменный (можно заменить модель/алгоритм).
- `library` отвечает за обход папки, загрузку файлов, индекс и его кэш.
- `server` — тонкий слой над `library` + `matcher` (auth, ограничения размера, сериализация).
- Как подтянуть `gmagc_common` в `flet build` (пути, зависимости), проверяется на этапе плана. Запасной вариант: скрипт копирует пакет в оба приложения перед сборкой.

## 5. Поток данных

1. Сервер стартует на ПК (порт по умолчанию 8765, слушает LAN). Экран «Подключение» показывает QR с адресом и кодом и те же данные текстом.
2. Телефон сканирует QR или вводит IP и код вручную. Адрес и код запоминаются.
3. Телефон снимает кадр, уменьшает до ~1280 px по длинной стороне, отправляет JPEG.
4. Сервер возвращает top-N результатов. Тот же результат виден в окне на ПК в ленте запросов.

### API (все методы кроме `/api/health` требуют `Authorization: Bearer <код>`)

- `GET /api/health` → `{version, indexed, count}`
- `GET /api/status` → состояние и прогресс индексации
- `POST /api/match` (multipart, поле `image`) → `{request_id, region_found, took_ms, results:[{id, name, path, vendor, score, copies:[path…], thumb_url}]}`
- `GET /api/image/{id}?size=thumb|full` → файл. Отдаются только файлы из индекса (нет обхода путей).

Безопасность: код доступа (8 символов) генерируется при запуске, трафик только в локальной сети, HTTPS не используется. Ограничение размера тела запроса. Никакого облака.

## 6. Алгоритм распознавания

### 6.1 Данные (замеры по `gobos/` и `photo/`)

- Библиотека: 11 192 изображения (PNG 8 361 + BMP 2 831), размеры 256×256 (6 703), 128×128 (4 050), 143×116 (243) и другие. Режимы: RGBA 6 753, P 1 872, RGB 1 633, L 934. У ~80% PNG **прозрачный фон**. ~10% цветных, ~2 300 почти бинарных. Точных дублей по md5 63 группы, визуальных дублей (одно гобо у разных производителей) заметно больше. Служебные файлы (`.allow_resource_update`, `question.bmp`) игнорируются.
- Фото: 17 штук, 2560×1920, одна и та же стена и ракурс. Светло-голубая проекция; узор состоит из отдельных пятен; внизу часто перекрывается уступом с оранжевым бликом; сверху луч света; фон (потолок, стеллажи).

### 6.2 Загрузка и нормализация

**Библиотека:** открыть файл → RGBA композитим на чёрный → яркость (для цветных используется яркость) → маска яркости.
**Фото:** уменьшить до ~1024 px → выделить «яркое и малонасыщенное» (порог по яркости + ограничение насыщенности, исключает оранжевые блики) → морфология → объединить пятна крупным дилатированием → взять кластер с наибольшей площадью (при равенстве ближе к центру) → вырезать с полями. Если кластер не найден, возвращаем `region_found=false`.

**Общее для обеих сторон:** сдвиг по центроиду маски, масштаб по описанной окружности, квадрат 224×224, серый уровень внутри области, чёрный вне. Чёрный диск и кольцо библиотеки не влияют на результат.

### 6.3 Модель и индекс

- Модель: предобученный энкодер изображений в формате **ONNX**, запуск через `onnxruntime` (PyTorch не используется). Выбор среди кандидатов (DINOv2-small, CLIP ViT-B/32 image encoder, лёгкая CNN вроде MobileNetV3) фиксируется бенчмарком на первом этапе. Требования: лицензия разрешает распространение с приложением, размер не критичен для ПК-сборки.
- Индексация **один раз**: по одному вектору на файл (~11 тыс.), кэш на диске (`float16`) в каталоге пользовательских данных, инкрементальное обновление по `(путь, mtime, размер)`. Индексация идёт в фоне с прогрессом и отменой.
- Группировка похожих: файлы с близкими нормализованными масками и векторами объединяются в «семейство»; в выдаче одна карточка и список всех путей («ещё N файлов»). Порог подбирается по бенчмарку.

### 6.4 Поиск

1. Фото → нормализация → **24 поворота × зеркало** (48 вариантов запроса) → эмбеддинги.
2. Косинусное сходство со всей матрицей индекса (numpy), для каждого гобо берётся лучший из 48 вариантов.
3. Top-K (около 20) уточняются сравнением масок: подбор поворота и зеркала (грубый шаг 5°, затем уточнение), метрика IoU/Chamfer.
4. Итоговый балл — смесь нейронного сходства и совпадения формы. Веса подбираются по бенчмарку. Возвращаем top-N (по умолчанию 10) с процентами.

Целевое время поиска после индексации: порядка секунд на обычном ПК. Это цель, а не гарантия, подтверждается замером.

### 6.5 Известные ограничения

- Похожие вариации одного узора могут идти рядом в top-5. Поэтому выдача — список, а не одна позиция.
- Цветные гобо (цветовые колёса и т.п.) по яркости слабо различаются. Цветовой признак добавляется отдельным этапом, если бенчмарк покажет проблему.
- Тонкие гобо (мелкая сетка, «rain») плохо видны на фото; качество зависит от съёмки.

## 7. Интерфейс

**ПК.** Слева источник изображения (файл, перетаскивание, буфер). В центре фото с подсвеченной найденной областью и список результатов. Карточка: превью, название, кликабельный путь (Проводник/Finder с выделением файла), процент, «ещё N файлов». Справа лента запросов с телефона. Настройки: папка библиотеки, число результатов, статус и пересборка индекса, порт, QR.
**Телефон.** Подключение (QR/IP + код) → экран камеры с кнопкой «снять» → результаты (превью, название, путь текстом с кнопкой «копировать», так как файл лежит на ПК).

## 8. Обработка ошибок

- Проекция не найдена → сообщение с советом переснять ближе и затемнить фон.
- Сервер недоступен, неверный код → экран переподключения.
- Битые файлы библиотеки → пропускаются, количество показывается в статусе.
- Индексация не блокирует UI; при закрытии программы прерывается корректно.
- Слишком большое изображение → отказ с понятной ошибкой.

## 9. Тестирование

- `pytest`: препроцессинг, нормализация, поиск, работа с индексом, API сервера (FastAPI TestClient). UI проверяется дымовыми тестами.
- Скрипт `scripts/benchmark.py`: метрики top-1/top-5 на (а) синтетических искажениях библиотеки (перспектива, размытие, шум, блики, оттенок, поворот, зеркало, засветка, обрезка), (б) 17 реальных фото с разметкой правильных ответов. Разметку готовим вместе с пользователем по первому прогону. Порог качества назначается после первого замера.
- В CI используются только синтетические данные (библиотека и фото в git не хранятся).

## 10. Сборка и репозиторий

- `ci.yml`: линтер (ruff) и тесты на каждый push/PR, Python 3.12.
- `build.yml`: по тегам `v*` и вручную. Матрица: Windows → `flet build windows`, macOS → `flet build macos`, Android → `flet build apk`. Артефакты прикрепляются к GitHub Release.
- Python закрепляется на 3.12 (`requires-python`) из-за доступности бинарных колёс. Текущий пустой `.venv` на Python 3.14 пересоздаём.
- Модель ONNX включается в сборку (Git LFS или скачивание в CI с проверкой контрольной суммы). В работе интернет не нужен.
- Ограничения: macOS-приложение без подписи Apple (Gatekeeper предупредит при первом запуске), APK без release-подписи (ключ добавляется секретом позже).
- В git **не** коммитятся `gobos/` и `photo/` (`.gitignore`).

## 11. Риски и что проверить в первую очередь

1. **Качество нейросети на абстрактных формах.** Проверяется бенчмарком до построения остального (этап 1). Запасной вариант — дообучение лёгкой модели на синтетических «плохих фото» и замена ONNX-файла без смены интерфейса.
2. **Сегментация проекции** на реальных фото (мультипятенные узоры, блики, обрезка).
3. **QR-сканирование внутри Flet-приложения** не проверено. Ручной ввод IP + кода остаётся обязательным запасным вариантом.
4. **HTTP по локальной сети на Android:** система по умолчанию блокирует незашифрованный трафик; нужно разрешить cleartext для клиента (проверить настройку в `flet build`).
5. **Брандмауэр Windows / разрешение локальной сети на macOS** при первом запуске сервера: нужна подсказка пользователю.
6. **Общий пакет в `flet build`** и наличие колёс `onnxruntime`/`opencv` для ПК-сборок в упаковке Flet.
7. **Лицензия и размер модели.** Проверяется при выборе.
