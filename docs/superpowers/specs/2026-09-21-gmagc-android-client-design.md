# GMAGC: Android-клиент (этап 5). Дизайн

Дата: 2026-09-21. Статус: дизайн утверждён в диалоге (с добавлением приближения и фокуса камеры), реализация начата.
Продолжение `2026-09-19-gmagc-gobo-recognizer-design.md` (раздел 7) и `2026-09-21-gmagc-phone-server-design.md`. Готовы: ядро, сборки, ПК-приложение с поиском и сервером (v0.4.0).

## 1. Цель

Телефон на Android подключается к ПК по Wi-Fi (QR или адрес и код), снимает проекцию камерой (с приближением и фокусом) или берёт фото из галереи, получает результаты поиска и копирует путь найденного файла.

## 2. Находки разведки

1. Прежние APK не могли работать с камерой: в манифесте нет `android.permission.CAMERA` (нужен `permissions = ["camera"]` в `[tool.flet]`).
2. HTTP без шифрования разрешается без своего шаблона: шаблон сборки Flet 1.0.0 читает `[tool.flet.android.manifest_application]`; достаточно `usesCleartextTraffic = "true"`.
3. Готового QR-сканера для Flet нет, но на `pypi.flet.dev` есть Android-колёса `pyzbar` и `Pillow` для Python 3.12 под все ABI: QR читается на телефоне из снимка камеры.
4. Flet Camera даёт `set_zoom_level`, `get_min/max_zoom_level`, `set_focus_mode`, `set_focus_point`, `set_exposure_point`, `take_picture`; жесты дают `GestureDetector` (`on_tap_down`, `on_scale_*`).

## 3. Решения

| Вопрос | Решение |
|---|---|
| Экран | Один экран Flet с тремя видами: подключение, камера, результаты |
| Подключение | «Считать QR» (снимок камерой + `pyzbar`) или поля «Адрес ПК» и «Код»; проверка `/api/health` и `/api/status`; адрес, порт и код запоминаются (`SharedPreferences`), при запуске подключение восстанавливается само |
| Сеть | Клиент на `http.client` (без новых зависимостей), типизированные ошибки, протокол из `gmagc_common` |
| Камера | Задняя, `ResolutionPreset.HIGH` (1280×720); **приближение**: ползунок, кнопки «+»/«−», щипок двумя пальцами; **фокус**: касание по кадру наводит фокус и замер экспозиции (с меткой на кадре), кнопка «Фокус: авто / зафиксирован» |
| Галерея | `FilePicker` (системный выбор фото); файл больше 8 МБ уменьшается Pillow (лимит сервера 10 МБ) |
| Результаты | Карточка: превью, имя, путь, оценка, «ещё N копий»; **клик по карточке и кнопка «Копировать путь» кладут в буфер абсолютный путь с именем файла** (как на ПК) |
| Ошибки | Понятные тексты: нет связи (Wi-Fi, брандмауэр, приложение на ПК), неверный код, пауза после 5 попыток, индекс на ПК не построен, слишком большой файл; строка «последняя ошибка» для диагностики на телефоне |
| Сборка Android | `permissions = ["camera"]`, `usesCleartextTraffic`, зависимости `pyzbar`, `Pillow`; APK по ABI остаётся этапу 6 |
| Общий протокол | Копия `apps/mobile/src/gmagc_common` в `sync_common.py` и в тесте на совпадение; в протокол добавляются константы исходов `OUTCOME_*` |

## 4. Модули `apps/mobile/src/gmagc_mobile/`

- `client.py`: `GmagcClient(connection)`: `health()`, `status()`, `verify()`, `match(image, top=None)`; `ClientError(kind, message, retry_after)`, виды: `unreachable`, `unauthorized`, `rate_limited`, `no_index`, `bad_image`, `too_large`, `server`, `protocol` (в том числе чужой сервер и несовместимая версия API).
- `store.py`: `ConnectionStore(prefs)`: `load()`, `save(connection)`, `clear()`; повреждённые данные дают `None`.
- `qr.py`: `decode_qr(image)`, `connection_from_qr(image)`; `QrUnavailable`, если `pyzbar` не загрузился (тогда приложение просит ввести адрес вручную).
- `imaging.py`: `prepare_upload(data, limit=8 МБ)`.
- `camera.py`: `CameraController`: `start()` (разрешение, задняя камера, диапазон приближения), `set_zoom`, `zoom_by`, `focus_at(x, y, width, height)`, `toggle_focus_lock()`, `take_picture()`, `pause()`, `resume()`.
- `texts.py`: тексты ошибок, исходов, строки состояния.
- `app.py`: `MobileApp` (виды, обработчики, жесты) и `build_page`.

## 5. Тестирование

- Клиент на настоящем сервере `127.0.0.1` (все ошибки, лимит попыток, чужой сервер, версия API).
- Хранилище, `imaging`, `CameraController` на заглушках; QR: снимок QR из `segno` декодируется `pyzbar` (тест пропускается, если библиотека zbar не установлена; в CI ставится).
- Экран на заглушках: подключение (ручное, QR, автоматическое, ошибки), съёмка, результаты, копирование пути, галерея, приближение (ползунок, кнопки, щипок), фокус (касание, метка, блокировка), «Сменить ПК».
- Живая проверка: мобильное приложение запускается на Windows (`flet run`) и работает с собранным ПК-приложением по LAN-адресу (демо-переменные `GMAGC_MOBILE_DEMO_LINK`, `GMAGC_MOBILE_DEMO_PHOTO`).
- CI собирает APK; из артефакта разбирается бинарный манифест: `CAMERA` и `usesCleartextTraffic="true"`.
- Не проверяется без телефона: камера, приближение, фокус, `pyzbar` и сеть на реальном Android (проверяет пользователь на своём телефоне).

## 6. Вне объёма

Deep-link из системной камеры, автообнаружение по mDNS, история запросов на телефоне, вспышка, APK по ABI и подпись (этап 6).
