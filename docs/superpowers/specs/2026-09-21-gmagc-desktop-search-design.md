# GMAGC: ПК-приложение с поиском (этап 3). Дизайн

Дата: 2026-09-21. Статус: дизайн утверждён в диалоге; реализация начата.
Продолжение `2026-09-19-gmagc-gobo-recognizer-design.md` (разделы 5–8) и `2026-09-21-gmagc-builds-design.md`. Ядро (v0.1.0) и каркасы со сборками (v0.2.1) готовы.

## 1. Цель

ПК-приложение, в котором можно выбрать папку библиотеки гобо, построить индекс, выбрать фото проекции и увидеть лучшие совпадения: превью, имя, кликабельный путь, оценка. Сервер и подключение телефона это этап 4; слой сервиса, введённый здесь, будет общим для окна и сервера.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Ввод фото | Кнопки «Выбрать фото» и «Вставить из буфера» (картинка или скопированный в Проводнике файл). Перетаскивания файлов из ОС во Flet 1.0.0 нет: `DragTarget` работает только внутри приложения |
| Настройки и кэш | `%LOCALAPPDATA%\@ANDY_BUM\GMAGC\` (macOS `~/Library/Application Support/GMAGC`, иначе `~/.local/share/gmagc`), переопределение переменной `GMAGC_DATA_DIR`; `settings.json` (папка библиотеки, число результатов, по умолчанию 10) и `index.npz` |
| Долгие операции | Индексация и поиск в фоновом потоке (`page.run_thread`), прогресс и отмена |
| Порог «нет совпадения» | Результаты не скрываются. При оценке первого ниже **72%** показывается предупреждение (по замерам верные ≥ 70,5%, ложные ≤ 71,3%, порог нестрогий) |
| Вектор признаков | Пиксельный 16×16 (как в v0.1.0), нейросеть не используется |
| Язык интерфейса | Русский |

## 3. Слой сервиса (`gmagc_desktop/service/`, без Flet)

- `settings.py`: `data_dir()`, `Settings(library_dir: str = "", top_n: int = 10)`, `load_settings(path)` / `save_settings(settings, path)`. Повреждённый файл настроек даёт настройки по умолчанию.
- `results.py`: `Outcome` (`FOUND`, `LOW_CONFIDENCE`, `NO_PROJECTION`), `Result(rank, name, rel_path, full_path, score, copies, thumbnail_png)`, `SearchOutcome(kind, results, projection_png, took_ms)`, `LOW_CONFIDENCE_SCORE = 0.72`.
- `search_service.py`: `SearchService(data_dir, embedder=None)`: `load()` (настройки и кэш индекса), `set_library(path)`, `build_index(progress, cancel)` (дозапись поверх кэша, сохранение), `status()` (`IndexStatus`: файлов, семейств, пропущено, временно нечитаемых), `search_photo(bgr, top_n)`, `search_file(path)`, `search_image_bytes(data)`. Исключения: `PhotoError(ValueError)` для нечитаемого фото, `NoIndexError(RuntimeError)`, если индекса нет.
- `reveal.py`: `reveal_in_file_manager(path)`: Windows `explorer /select,`, macOS `open -R`, иначе открыть папку.
- Миниатюры: `matcher/thumbnail.py::thumbnail_png(gray, size)` (квадрат с чёрными полями, PNG); `scripts/_thumbs.py` использует ту же функцию.

## 4. Экран (`gmagc_desktop/ui/`)

Тонкий слой над сервисом, без бизнес-логики.
- **Слева:** папка библиотеки, «Выбрать папку», «Обновить индекс», статус («11 178 файлов, 9 396 семейств»), индикатор индексации и «Отмена».
- **Справа:** «Выбрать фото», «Вставить из буфера», исходное фото и найденная проекция, ниже список результатов: превью, имя, путь (клик открывает файловый менеджер с выделением), оценка в процентах (не больше 100), «ещё N копий» (пути в подсказке). Предупреждение о низкой оценке (жёлтое) и сообщение «проекция не найдена: переснимите ближе, затемните фон».
- **Внизу:** версия, автор, кнопка «Проверить ядро» (сохраняет проверку упаковки из v0.2.x).
- Ошибки (папка недоступна, пустая, нечитаемое фото, нет индекса) показываются сообщением в окне, без traceback.

## 5. Отложенные исправления ядра (первая задача этапа)

1. Обрезанные PNG/BMP (`OSError` без `errno`, текст `truncated` / `broken data stream` / `decoder error`) считаются окончательным пропуском, а не «временно нечитаемыми».
2. `load_index` отвергает кэш, где `rel_path` абсолютный или содержит `..` (кэш строится заново); сервис дополнительно проверяет, что полный путь лежит внутри папки библиотеки.
3. «Загрузить или построить индекс» переезжает из `scripts/benchmark.py` в пакет (`library/cache.py::update_index`), скрипт становится тонкой обёрткой.
4. `save_index` пишет через уникальный временный файл (две пересборки не портят друг друга).

## 6. Тестирование

- Тесты сервиса на синтетической библиотеке (`tests/fixtures.py`): настройки, индексация с прогрессом и отменой, поиск (найдено / низкая оценка / нет проекции), результаты и копии, ошибки.
- Тесты экрана на заглушке страницы: клики, состояния, сообщения.
- Дымовой запуск собранного приложения уже есть в CI (Windows, macOS).
- Визуальная проверка: снимок **только окна** приложения после локальной сборки.

## 7. Вне объёма

Сервер и лента запросов с телефона, QR-код (этап 4); перетаскивание файлов из ОС; число результатов в интерфейсе; цветовой признак; дообучение; подписи сборок.
