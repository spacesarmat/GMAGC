# GMAGC: сервер для телефона (этап 4). Дизайн

Дата: 2026-09-21. Статус: дизайн утверждён в диалоге (с правками пользователя), реализация начата.
Продолжение `2026-09-19-gmagc-gobo-recognizer-design.md` (разделы 4, 5, 8) и `2026-09-21-gmagc-desktop-search-design.md`. Готовы: ядро, сборки (v0.2.1), ПК-приложение с поиском (v0.3.0).

## 1. Цель

ПК-приложение принимает фото от телефона по Wi-Fi, ищет гобо и возвращает результаты; те же результаты появляются в окне ПК. Клиент на телефоне это этап 5; здесь его заменяет скрипт `scripts/phone_sim.py`.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Запуск сервера | **Автоматически при старте приложения** (по решению пользователя); переключатель в окне выключает и запоминает выбор (`server_enabled`, по умолчанию `true`) |
| Код доступа | 8 символов без похожих (`0/O`, `1/I/L`), **постоянный**, лежит в `settings.json`, кнопка «Новый код» |
| Порт | 8765; если занят, пробуются следующие 9 (фактический порт показывается в окне и QR) |
| Транспорт | Обычный HTTP по локальной сети, без HTTPS, без облака |
| Сервер | Стандартная библиотека (`http.server.ThreadingHTTPServer`), не FastAPI: у FastAPI зависимость `pydantic-core` в сборках Flet, а с OpenCV уже был сбой упаковки |
| Фото в запросе | Тело запроса это сам JPEG/PNG (не multipart) |
| Превью в ответе | Внутри JSON (base64), отдельного `/api/image` нет: не нужна защита путей |
| QR | Пакет `segno` (чистый Python, PNG без Pillow), ссылка `gmagc://connect?host=…&port=…&code=…` |
| Общий протокол | `packages/common/gmagc_common` (только стандартная библиотека); копии в `apps/*/src/gmagc_common` синхронизирует `scripts/sync_common.py`, тест следит за совпадением; шагов копирования в сборках нет |
| Клик по найденному файлу | **Копирует в буфер обмена абсолютный путь файла (с именем файла)**, одинаково на Windows и macOS; открытие папки вынесено в отдельную кнопку карточки |

## 3. Протокол (`gmagc_common`)

Константы: `API_VERSION = 1`, `DEFAULT_PORT = 8765`, `CODE_LENGTH = 8`, `CODE_ALPHABET`, `MAX_IMAGE_BYTES = 10 МБ`.
Код: `normalize_code` (верхний регистр, без пробелов и дефисов), `format_code` (`ABCD-2345`), `is_valid_code`.
Подключение: `build_link(host, port, code)`, `parse_link(text)` (для QR), `parse_address(text)` (ручной ввод `192.168.1.5` или `192.168.1.5:8765`); неверный ввод даёт `None`.
Ответы (`to_dict` / `from_dict`, превью в base64): `ResultItem(rank, name, path, score, copies, thumbnail_png)`, `MatchResponse(request_id, outcome, took_ms, results, projection_png)`, `Health(app, api, version, indexed, files)`, `Status(indexed, files, families, indexing, done, total)`, `ApiError(code, message)`.
Коды ошибок и статусы HTTP: `unauthorized` 401, `bad_request` 400, `bad_image` 400, `not_found` 404, `too_large` 413, `rate_limited` 429, `no_index` 409, `server_error` 500.

## 4. API сервера (`gmagc_desktop/server/`)

Все ответы JSON в UTF-8; ошибки `{"error": код, "message": текст}`. Все методы кроме `/api/health` требуют `Authorization: Bearer <код>`.
- `GET /api/health` → `Health`.
- `GET /api/status` → `Status` (идёт ли индексация, прогресс).
- `POST /api/match[?top=N]`, заголовок `Content-Length` обязателен, тело изображение → `MatchResponse` (`outcome`: `found` / `low_confidence` / `no_projection`, до `top` результатов, по умолчанию `top_n` из настроек, максимум 50).

Защита: сравнение кода за постоянное время (`hmac.compare_digest`); после 5 неверных попыток с одного адреса 429 на 30 с (`Retry-After`); лимит тела 10 МБ проверяется по `Content-Length` до чтения; таймаут чтения сокета 15 с; JSON вместо HTML для всех ошибок протокола (`send_error` переопределён); один поиск за раз.
Порты: на Windows `SO_REUSEADDR` выключен (иначе два сервера тихо садятся на один порт).

`PhoneServer(service, on_request=None)`: `start(port) -> int` (фактический порт, `ServerStartError`, если свободного нет), `stop()`, `running`, `port`. Сервер работает в фоновом потоке. `on_request(RequestRecord)` вызывается после ответа телефону; исключения обратного вызова логируются и не ломают сервер.
`RequestRecord(request_id, time, client, photo, outcome)` (`outcome` типа `SearchOutcome`).
Адреса: `lan_addresses()`: основной адрес маршрута первым, остальные IPv4 без loopback и link-local; работает без интернета.

## 5. Сервис

- `Settings` расширяется: `server_enabled=True`, `port=8765`, `access_code=""`; повреждённые значения заменяются значениями по умолчанию (код проверяется на алфавит и длину).
- `SearchService`: `ensure_access_code()`, `reset_access_code()`, `set_server_enabled(bool)`; замок вокруг поиска и подмены индекса (закрывает отложенный пункт про пересборку индекса при работающем сервере: поиск держит замок, индексация подменяет индекс только в конце); `indexing_state()` для `/api/status`.

## 6. Экран

- Левая колонка (теперь с прокруткой): блок **«Телефон»**: переключатель «Сервер для телефона», строка состояния («Работает: 192.168.1.5:8765», «Выключен», «Не удалось запустить: …»), QR, «Код: ABCD-2345», кнопки «Копировать код» и «Новый код», другие адреса ПК текстом, подсказка про Wi-Fi и брандмауэр Windows. Ниже **«Запросы с телефона»**: последние 10 (время, адрес, первое совпадение и оценка); клик открывает результат в основном окне.
- Запрос с телефона сразу показывается в основном окне (фото, проекция, результаты) с подписью «Запрос с телефона …».
- Карточка результата: **клик по карточке копирует абсолютный путь файла в буфер**, над списком показывается «Путь скопирован: …»; кнопка «Показать в папке» (значок папки) открывает файловый менеджер.
- Сервер стартует в `build()`, если `server_enabled`; из потока сервера экран обновляется через `page.update()`, как из рабочих потоков индексации.

## 7. Скрипт `scripts/phone_sim.py`

`phone_sim.py --link gmagc://… photo.jpg` или `--host --port --code`; уменьшает фото до 1280 px по длинной стороне (как телефон), отправляет `/api/match`, печатает исход, время и таблицу результатов. Коды выхода: 0 успех, 1 ответ сервера с ошибкой (401, 409 и др.), 2 нет соединения, 3 неверные аргументы или нечитаемое фото. Нужен для проверки без телефона и для отладки этапа 5.

## 8. Тестирование

- Общий пакет: коды, ссылки, ответы (туда и обратно), совпадение копий с оригиналом.
- Сервер на реальном сокете `127.0.0.1` (порт 0): все маршруты, коды ошибок, неверный и пустой код, лимит попыток, лимит размера, параллельные запросы, занятый порт, остановка; порт-fallback.
- Экран на заглушке страницы: автозапуск, переключатель, история, копирование пути (`os.path.abspath`), кнопка «Показать в папке», новый код.
- Живая проверка: локальная сборка Windows, запуск, `phone_sim.py` по LAN-адресу ПК с реальным фото, снимок окна.

## 9. Вне объёма

Android-клиент и обход cleartext HTTP (этап 5), HTTPS, автообнаружение по mDNS, несколько именованных телефонов, сохранение истории запросов между запусками, крупный просмотр гобо на телефоне.
