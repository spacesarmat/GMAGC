# GMAGC: редактор профилей приборов на телефоне (этап 1). Дизайн

Дата: 2026-09-24. Статус: черновик, ждёт утверждения пользователем.
Продолжение `2026-09-21-gmagc-android-client-design.md`. Готово: ПК-приложение и Android-клиент (v0.6.20).

## 1. Цель

В мобильном приложении появляется новое окно «Профили приборов», где можно с нуля создать профиль прибора (fixture type) для grandMA2 и grandMA3: производитель, модель, режимы, каналы, диапазоны значений. Профили хранятся на телефоне и редактируются в любой момент.

Этот этап делает **только редактор и модель данных**. Экспорт в XML пультов, отправка на ПК, гобо-колёса из библиотеки GMAGC и импорт из Open Fixture Library вынесены в следующие этапы (раздел 8).

## 2. Решения

| Вопрос | Решение |
|---|---|
| Порядок работ | **Сначала редактор** (решение пользователя), экспорт следом |
| Целевые пульты | grandMA2 и grandMA3. Модель не привязана к пульту; писатели XML для каждого пульта добавляются отдельно |
| Создание | **С нуля на телефоне** (решение пользователя); OFL-импорт остаётся бонусом на потом |
| Где живёт модель | `packages/common/gmagc_common/fixtures.py` (стандартная библиотека), копии в `apps/*/src/gmagc_common` синхронизирует `scripts/sync_common.py`; ПК позже использует ту же модель для экспорта |
| Формат хранения | JSON (`to_dict` / `from_dict`), XML пультов только выходной формат, обратно не разбирается |
| Хранилище на телефоне | SharedPreferences тем же способом, что `ConnectionStore` (индекс профилей + по ключу на профиль), проверяется на `FakePrefs` |
| Окно | Ещё один overlay мобильного приложения (как «Галерея» и «Настройки»), кнопка входа в главном меню |
| Ввод каналов | Через **шаблоны каналов**: шаблон задаёт атрибут, разрядность и типовые диапазоны |

## 3. Модель данных (`gmagc_common/fixtures.py`)

- `FixtureProfile(manufacturer, name, short_name, modes)`; `id` (uuid) присваивается при создании и не меняется.
- `Mode(name, channels)`; порядок каналов = порядок в списке.
- `Channel(dmx, bits, name, template, default, ranges)`:
  - `dmx` — первый DMX-адрес канала, 1–512;
  - `bits` — 8 или 16 (16 бит занимает `dmx` и `dmx+1`, тонкий канал не описывается отдельно);
  - `template` — идентификатор шаблона из раздела 4;
  - `default` — значение по умолчанию, доля 0–255 грубого байта;
  - `ranges` — список `Range(start, end, name)` по грубому байту 0–255.
- Сериализация: `profile_to_dict` / `profile_from_dict`; `profile_from_dict` проверяет типы и отбрасывает повреждённые данные (`ProfileError`), как `settings_from_json` в ПК-приложении.

### Проверка (`validate_profile`, возвращает список ошибок с путём «режим → канал»)
- у профиля есть производитель, название и хотя бы один режим; в режиме есть хотя бы один канал;
- имена режимов уникальны в профиле; имена каналов не пустые;
- каналы не пересекаются по DMX-адресам (с учётом 16 бит), адреса в 1–512; **пропуски адресов допустимы** (предупреждение, не ошибка);
- диапазоны каждого канала лежат в 0–255, `start ≤ end`, не перекрываются; дыры допустимы (предупреждение);
- `default` попадает в 0–255.

## 4. Шаблоны каналов

Справочник в `gmagc_common/fixtures.py`: `TemplateId → (название по-русски, атрибут по умолчанию, разрядность по умолчанию, типовые диапазоны)`. Начальный набор: Dimmer, Shutter/Strobe, Pan, Tilt, Pan/Tilt speed, Red, Green, Blue, White, CTO, Color wheel, Gobo wheel, Gobo rotation, Prism, Focus, Zoom, Iris, Frost, Control, Custom.
Шаблон Custom не подставляет ничего; пользователь вводит всё сам. Точное сопоставление шаблонов с атрибутами grandMA2/MA3 уточняется на этапе экспорта по эталонным файлам, поэтому здесь атрибут хранится как нейтральный идентификатор.

## 5. Интерфейс

Экраны (каждый overlay в стиле существующих, с кнопкой «Назад» и поддержкой системной кнопки «Назад» как в `test_mobile_back_button.py`):
1. **Список профилей:** карточки (производитель, модель, число режимов), «Новый профиль», удаление с подтверждением.
2. **Профиль:** производитель, название, короткое имя; список режимов; «Добавить режим» и «Дублировать режим».
3. **Режим:** название и список каналов в порядке DMX; «Добавить канал» через выбор шаблона; автоподстановка следующего свободного адреса; сообщения проверки под списком.
4. **Канал:** шаблон (можно сменить), название, DMX, 8/16 бит, значение по умолчанию, список диапазонов (добавить, изменить, удалить).

Поведение:
- **Автосохранение** после каждого изменения (чтобы правки не терялись при сворачивании); отдельной кнопки «Сохранить» нет.
- Ошибки проверки показываются на месте (красным), но сохранению не мешают: черновик может быть неполным.
- «Поделиться профилем» отправляет JSON через существующий `share_text`. Это единственный способ вынести профиль до появления экспорта (этап 2–3).

## 6. Границы этапа (чего здесь нет)
Экспорт в MA2/MA3 XML; отправка на ПК и новый эндпоинт сервера; гобо-колёса из библиотеки GMAGC; импорт из OFL; геометрия, 3D-модели, матрицы пикселей, RDM; редактирование готовых XML.

## 7. Тесты
- `tests/common/test_fixtures.py`: сериализация «туда-обратно», повреждённые данные, все правила проверки, шаблоны.
- `tests/mobile/test_profile_store.py`: сохранение, список, удаление, повреждённый ключ не роняет загрузку (на `FakePrefs`).
- `tests/mobile/test_mobile_profiles_ui.py`: сценарии создания профиля, режима, канала и диапазонов на фейках из `tests/fakes_mobile.py`; кнопка «Назад» на каждом экране; автосохранение.
- Полный `pytest` и `ruff check .` проходят; `scripts/sync_common.py` синхронизирует копии (тест на совпадение уже есть).
