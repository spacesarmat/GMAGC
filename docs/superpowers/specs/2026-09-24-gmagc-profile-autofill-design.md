# GMAGC: автозаполнение профиля по инструкции (фото или PDF). Дизайн

Дата: 2026-09-24. Статус: подход одобрен пользователем (офлайн и облако по кнопке, ключ на ПК, сначала автозаполнение, потом гобо-колёса). Реализация начнётся после образцов страниц инструкции.
Продолжение `2026-09-24-gmagc-fixture-editor-design.md`.

## 1. Цель

Быстро создать профиль прибора по странице инструкции: в режиме выбрать «Заполнить по инструкции», снять страницу камерой (или выбрать фото/PDF), получить **черновик каналов** и одним нажатием добавить нужные в режим. **Одна страница может описывать много каналов** (таблица режима целиком) и даже несколько режимов: единица разбора — таблица, а не один канал.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Где работает | Распознавание на **ПК**: тяжёлые библиотеки не тащим на телефон; телефон шлёт страницу по уже готовому каналу связи |
| Метод | `POST /api/fixture-scan`: тело — JPEG/PNG или PDF (до 20 МБ), запрос `?engine=local|cloud`, ответ — `ScanDraft` (список каналов-кандидатов и предупреждения) |
| Офлайн-движок | PDF с текстовым слоем: текст и таблицы напрямую (без распознавания); фото и сканы: OCR на ПК. Выбор библиотеки OCR (RapidOCR/ONNX, Tesseract или Windows OCR) и разбор строк таблицы правилами уточняются на образцах пользователя |
| Облачный движок | Только **по кнопке** «Улучшить в облаке» после офлайн-черновика (или сразу, если пользователь выбрал облако). Модель Claude с изображениями и структурированным ответом (JSON по схеме кандидатов). Ключ API вводится на **ПК** в «Настройках», хранится в настройках ПК, на телефон не передаётся; страницы уходят на серверы Anthropic только после нажатия |
| Черновик | `DraftChannel(dmx, bits, name, template, ranges, confidence, source_text)`; правила угадывания шаблона по названию («Pan», «Pan fine» → один 16-битный канал, «Gobo wheel» → колесо гобо, «Dimmer», «Shutter/Strobe»…), диапазоны из строк вида `0–9 open`, `10–19 gobo 1` |
| Несколько режимов | Если на странице несколько таблиц/заголовков режимов, черновик содержит группы; пользователь выбирает, какие добавить в какой режим; черновики нескольких страниц накапливаются |
| Экран проверки на телефоне | Список кандидатов с галочками, правка шаблона/адреса/названия/диапазонов, «Добавить в режим»; профиль не меняется без подтверждения; пересечения адресов ловит обычная проверка профиля |
| Приватность | Облако включается явно, по кнопке, с подтверждением («страница уйдёт в Anthropic»); ключ не логируется; без ключа кнопка неактивна |
| Языки | Все тексты через `t("…")`, инструкция может быть на русском или английском (OCR и облако получают оба языка) |

## 3. Порядок работ (каждый шаг — отдельный PR)

1. Модель `DraftChannel`/`ScanDraft` и правила угадывания шаблона и диапазонов (чистый код, тесты на примерах строк таблиц).
2. Офлайн-разбор: PDF с текстом и таблицами; затем OCR фото.
3. Метод `POST /api/fixture-scan` и клиент телефона.
4. Экран проверки на телефоне («Заполнить по инструкции» в режиме).
5. Облачный движок и поле ключа в настройках ПК.
6. Релиз.

## 4. Риски

- Качество OCR на фото мануалов (мелкий шрифт, перспектива): ожидаем средний результат, поэтому экран проверки обязателен, а облако — запасной вариант.
- Размер сборки ПК-приложения с OCR: библиотека и модели добавят десятки мегабайт; выбор откладывается до образцов и замера.
- Точный формат таблиц в мануалах разных производителей: набор правил растёт на реальных образцах.

## 5. Что нужно от пользователя

Образцы страниц инструкции (2–3 штуки): фото таблицы DMX, PDF с текстом и, если есть, страница, где в одной таблице несколько режимов. Они станут тестовыми данными и покажут, где правила ломаются.
